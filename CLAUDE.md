# sparkrun-tensorfold-plugin: agent rules

A sparkrun runtime plugin that launches tensorfold inference engines across one or more nodes. The
package is generic: it must contain no cluster-, user-, model- or fork-specific values. Engine
profiles live in their own packages, never here; `examples/` holds a fictional one.

## Layers

* Core (`runtime.py`, `commands.py`, `fabric.py`, `recipe_block.py`, `artifacts/`) knows sparkrun,
  ranks, trust, readiness and artifact lifecycle. It MUST NOT name a model, a fork, a binary, a
  flag, an environment variable, or a path of any engine.
* The profile contract (`profiles/model.py`, `profiles/scripts.py`, `profiles/__init__.py`) is
  generic. An engine variant's contract is written down only in a profile package, which registers
  itself through `register_profile`. This repository ships none; the tests use
  `examples/profile-plugin`.
* Recipes hold values only.

## Rules (full text in `.claude/rules/`)

* `ssot.md`: one declaration site per concept; audit greps must return zero matches.
* `no-fallbacks.md`: a missing or invalid value raises. No default substitutions.
* `testing.md`: a test is valid only if it fails when the behavior it checks is broken.
* `release-trigger-model.md`: which conventional-commit types open a release PR.

## Commits

* Conventional commits, imperative mood, lowercase subject, no trailing period, header at most 72
  characters, body lines at most 100.
* No AI / Claude / LLM attribution in commit messages or PR bodies. No emoji.
* Do not pass `--no-verify`. If a hook fails, fix the cause.
* `CHANGELOG.md` is generated by release-please. Never edit it.

## Verification commands

```sh
uv sync
uv run ruff check src tests examples && uv run ruff format --check src tests examples && uv run mypy src examples/profile-plugin/sparkrun_tensorfold_profile_hello_engine
uv run --with "sparkrun==0.3.10" pytest
uv run --with "sparkrun==0.4.1" pytest
```

Tests marked `docker` need a local Docker daemon.

## Security

* The plugin never reads an API key file. It only bind-mounts the path the recipe names.
* Never write secrets into job metadata, recipe exports, logs, or test fixtures.
